# Covi 0.3.0 — From slides to direction, and broadcast-quality sound

Status: approved (self-approved under the owner's standing approval; see `../rulings.md`, R-001).
Date: 2026-10-09. Base: `main` at aeef1fa (v0.2.0).

## 1. Intent

What the owner asked for (verbatim scope, not reinterpreted):

- Videos show code and changes visually instead of paging through cards.
- Sound is broadcast quality: a continuous, gently ducked bed; voice-band carve; glue compression; effects sitting under the voice.
- **Evidence decides what is shown; the agent decides how it is shown.** An agent writes a bounded, schema-validated `video/direction.json`; Covi renders it deterministically (the `video/score.json` pattern). Every number, code token, and screen cites an evidence id. Brand is fixed (palette, type, fox, theme); choreography varies per change. Same inputs → same video; different change → different video.
- The agent never authors executable code, CSS, HTML, or URLs for the renderer. Repository content is untrusted and reaches the agent's prompt.

Success = the acceptance list (§17): the benchmark example renders in ko and en without looking like slides, the key number is the largest thing when it lands, code visibly morphs, the problem is shown, and the sound measures within the stated windows, deterministically, with `npm run check` green on every PR.

Assumptions I made (recorded as rulings): see `../rulings.md`.

## 3. Architecture overview

```
storyboard.json (agent or draft) ─┐
direction.json  (agent, optional) ├─► validate ─► resolve ─► timeline.json ─► runtime (canvas stage) ─► frames
evidence.json   (Covi)           ─┘   (schema,      (content from        (scenes + stops +
                                      refs)          evidence; times      resolved elements
default director (no direction) ──────────────►     from phrases)        and beats)
                                                                          │
timeline cues (incl. direction events) ─► sound (fit, effects, broadcast mix) ─► music.wav, master
```

- **New module** `packages/video/src/direction/`: `schema.ts` (Zod, `DIRECTION_LIMITS`), `refs.ts` (validation against storyboard + evidence), `resolve.ts` (direction → timeline direction), `director.ts` (default director), `stops.ts` (canvas stop layout), `layout.ts` (element layout inside a stop).
- **New runtime** `packages/video/src/runtime/canvas.ts` (world layer, camera between stops, viewport clip) and `runtime/direction/` (one file per element family: `code.ts`, `morph.ts`, `metric.ts`, `flow.ts`, `elements.ts`).
- **Core** gains metric evidence (`packages/core/src/evidence/metrics.ts`) and the `video.direction` config key. Core stays platform-independent and imports no other Covi package.
- **Audio** gains a music bus (glue compressor, voice-band carve), smoothed placement, loudness range and momentary loudness, and effect levels relative to the bed. Audio still imports no Covi package.
- Dependency direction unchanged: `brand` ← `video`, `audio` ← `video`; `core` ← `capture`, `video`, `platforms` ← `cli`.

## 4. The direction file (`video/direction.json`, schemaVersion 1) — PR B2 (+B3–B5 extend)

### 4.1 Shape

```jsonc
{
  "schemaVersion": 1,
  "draft": false,                 // true: written by Covi's default director (re-derived at render)
  "shots": [                      // at most one per storyboard scene; scenes without a shot get the default director's
    {
      "scene": "s3",              // a storyboard scene id
      "enter": "pan",             // pan | zoom | cut | fade | push | wipe | zoom-through (optional)
      "layout": "row",            // auto (default) | single | row | column | split
      "elements": [               // 1–8; content only from evidence (labels excepted)
        { "id": "req", "kind": "code", "evidence": "diff-hunk:src/request.js:12", "side": "head" },
        { "id": "bytes", "kind": "metric", "evidence": "metric:terminal-1:request-bytes", "show": "counter" }
      ],
      "beats": [                  // 0–12 verbs, in time order
        { "verb": "reveal", "element": "bytes", "at": "only ten kilobytes" },
        { "verb": "camera", "move": "zoom", "to": "bytes", "at": "ten kilobytes" }
      ]
    }
  ]
}
```

### 4.2 Elements

| kind | PR | content source | agent-written fields |
|---|---|---|---|
| `visual` | B2 | the scene's storyboard visual, drawn by the existing component | none |
| `code` | B2 | lines of a `diff-hunk:` item read from the run's `diff.patch`; `side`: `head` (default), `base`, or `diff`; optional `lines: [from, to]` (1-based, within the hunk) | none |
| `output` | B2 | a `terminal:<n>` (or `terminal:app-start-*`) item's command and output from `demo/captures.json`; `side`: `head` (default) or `base` | none |
| `capture` | B2 | a `screenshot:` item's image | none |
| `node` | B2 | — | `label` (§4.5); optional `evidence` ids it stands for |
| `label` | B2 | — | `text` (§4.5); optional `tone`: `neutral` \| `warning` \| `success` |
| `morph` | B3 | a `diff-hunk:` item, base → head, token level | none |
| `metric` | B4 | a `metric:` item; `show`: `counter` \| `bars` \| `compare`; `side` for single-value shows | optional `label` |
| `packet` | B5 | — | optional `label` |
| `pile` | B5 | a `metric:` item's value (`count`, `side`) | optional `label` |

A shot's content is its elements. A shot with no `visual` element replaces the storyboard visual for that scene; a shot can keep it as one element among others. Elements not targeted by a `reveal`/`stack`/`split` are present from the shot's start.

### 4.3 Verbs (beats)

Every beat may carry `at`: a phrase quoted verbatim from the scene's narration that occurs exactly once (the storyboard `sync` rule and resolver, `scenePhases`/`findPhrase`). Without `at`, beats are spread deterministically through the scene's line in order (§4.7).

| verb | PR | fields | what it draws |
|---|---|---|---|
| `place` | B2 | `element` | the element sits in place from the shot's start (explicit form of the default) |
| `reveal` | B2 | `element`, `style`: `rise` (default) \| `pop` \| `wipe` \| `type` | the element enters |
| `camera` | B2 | `move`: `zoom` \| `pan` \| `follow`; `to`: element; `zoom`: 1–2.5 (default: fit the element to the media region) | camera move inside the stop; `follow` tracks a moving target (morph's changed lines, a packet) |
| `morph` | B3 | `element` (a `morph`) | token-level base → head animation |
| `count` | B4 | `element` (a `metric`) | counter ticks base → head; bars grow or shrink with it |
| `flow` | B5 | `from`, `to` (nodes), optional `packet` | a packet travels the edge between two nodes (edge drawn if absent) |
| `split` | B5 | `element` (packet or node), `count`: metric id, `side` | one thing breaks into N pieces |
| `merge` | B5 | `element` (a split result or pile) | the pieces collapse into one |
| `stack` | B5 | `element` (a `pile`) | items pile up one by one to the metric's count |
| `count-up` | B5 | `element` (a `metric`), `side` | counter counts from 0 to one side's value |

Counts and numbers are never literal in the file: `split`, `stack`, `pile`, `count`, `count-up` take their numbers from `metric:` evidence. Drawn items cap at 12; the counter shows the true value.

### 4.4 `DIRECTION_LIMITS` (exported, single source; tests import it)

```
fileBytes 262144 · shots 24 · elementsPerShot 8 · beatsPerShot 12
id /^[a-z][a-z0-9-]{0,23}$/ · labelChars 32 · phraseChars 200 (as sync)
zoom [1, 2.5] · lines: from/to ints within the hunk, span ≤ 40 · drawnItems 12
evidence ids per element ≤ 4 (EVIDENCE_LIMITS.id length each)
```

All objects are `z.strictObject`; unknown keys are rejected. Enums everywhere a choice exists.

### 4.5 Agent-written text (labels)

`label` (node, packet, pile, metric) and `text` (label element): 1–32 characters after trim, from an allowlist — Unicode letters and marks (`\p{L}\p{M}`), spaces, and `-–—·,.'’:()/&+?!`. No digits (`\p{Nd}`, so no made-up numbers), no `<>{}[]"\`=@#$%^*|~;_`, no control characters. Strings containing `://` or starting with `www.` are rejected. Labels pass through the run's `Redactor` like the storyboard. The runtime sets all text with `textContent` (never `innerHTML`), so even a label that slipped past the allowlist renders as text.

Number words ("thirty") cannot be policed deterministically: the methodology forbids them in labels; this residual risk is recorded (R-012).

### 4.6 Validation (exit 2, `UsageError`, all problems listed at once)

1. Size ≤ `fileBytes` before parsing; JSON; Zod schema.
2. References: `scene` exists in the storyboard, at most one shot per scene; element ids unique within a shot; every beat references elements of the shot, of a compatible kind (e.g. `count` only a metric); `from`/`to` are nodes.
3. Evidence: every cited id exists in `evidence.json` with the expected kind (`code`/`morph` → `diff-hunk`, `output` → `terminal`, `capture` → `screenshot`, `metric`/counts → `metric`); requested `side` has a value; `lines` lie within the hunk.
4. Phrases: each `at` occurs exactly once in the scene's narration (without `[[…]]`); messages name shot and beat like `sync` messages do.
5. A direction with `"draft": true` is not validated against the current storyboard: Covi re-derives it with the default director at render, so a stale draft never blocks a render.

### 4.7 Resolution and timing

`resolveDirection(direction, storyboard, evidence, run files, layout timings)` → per scene a `SceneDirection` on `TimelineScene.direction`:

- Elements with concrete content (code lines and tokens, output text, image assets, metric values and units, labels) and a rect in stop-local stage pixels from `direction/layout.ts` (deterministic slot layout for `single`/`row`/`column`/`split`; `auto` picks from count and kinds).
- Beats with `t` (seconds since scene start) and `seconds` (duration): `at` → the phrase's caption time (same as `scenePhases`); missing `at` → evenly spaced over the speech window from 0.15 of it; a phrase lost to redaction falls back to the spaced slot (like phases, never an error at render).
- Everything resolved is redacted (`run.redactor.redactDeep`) before it is written into `timeline.json`.
- Direction never changes scene timing, except that a shot's `enter` is the scene's entrance kind and so shapes the overlap exactly like a storyboard `transition` does (R-008).

### 4.8 Default director (`direction/director.ts`)

Runs when `video.direction` is `auto` and `video/direction.json` is absent or `draft: true`. Pure and deterministic over (storyboard, evidence, review, seed). It:

- picks each scene's entrance (§5.3 rotation),
- keeps the storyboard visual and adds a `camera` beat where the visual has a target (marks, focus, highlights),
- (B3) turns code scenes that cite a small `diff-hunk:` into a `morph` shot with `camera follow`,
- (B4) adds a `metric` (`counter`/`compare`) to terminal scenes whose command has base and head metrics, choosing the metric with the largest relative change,
- (B5) turns diagram scenes into `node`s with `flow` beats along their edges, and adds `split`/`merge`/`stack` when a cited metric is a count that changes between base and head,
- never invents content: if evidence is missing, the scene keeps its visual.

`covi video --draft` writes `video/direction.json` with `"draft": true` beside the storyboard draft, for the agent to rewrite.

### 4.9 Configuration

`video.direction`: `auto` (default) | `off`. `off` renders exactly as 0.2.0 did (no canvas, no direction). CI and `--json` runs without an agent get the default director (interactive/non-interactive parity). Flag: `--direction auto|off` on `covi video` and `covi render`.

## 5. Canvas stage — PR B2

### 5.1 Model

The video is one large canvas. Each story scene is a **stop**: a frame-sized region in world coordinates, placed by `direction/stops.ts` along a deterministic path seeded by the timeline seed (so different changes travel differently): mostly to the right, turning down every 2–4 stops; the hero's stop is offset so the camera must pull back to reach it. Stops are separated by a gap of 0.25 frame widths. `TimelineScene.stop: { x, y }` records it (absent when `video.direction` is `off`).

### 5.2 Runtime

- `canvas.ts` adds a **world** layer: each scene's media layer is translated to its stop; the world is transformed by the camera (`translate` + `scale`, pure function of the frame).
- Header, narrator, captions, progress, and the hero accent stay in screen space.
- The viewport is clipped to the region the scene in front owns (`media`, or `full` for scenes without a header), interpolated across a transition, so a zoomed stop never covers captions or the narrator.
- Within a stop, the existing per-scene push and the direction's `camera` beats compose into the stop camera.
- No `Date`, no `Math.random`, no CSS transitions or animations; text set with `textContent`.

### 5.3 Entrances

`TransitionKind` gains `pan` (the camera glides to the next stop, 0.7 s) and `zoom` (the camera pulls back to show both stops and pushes into the next, 0.9 s); lengths live in `@covi/brand` `motion.transitions`. Existing kinds keep working. Default rotation (when neither shot nor storyboard sets one): the hero → `zoom`; before/after captures → `wipe`; a scene citing the same evidence as the previous → `cut`; otherwise alternate `pan` and `push`, so no kind exceeds 50% of story transitions; the outro keeps `fade`.

## 6. Code morph — PR B3

- Source: the hunk's base and head lines from `diff.patch` (already redacted).
- `direction/tokens.ts`: deterministic tokenizer (identifiers, numbers, strings, comments, punctuation, whitespace runs) and alignment: lines aligned by the hunk itself (context/del/add), tokens within a replaced line pair by LCS. Each token is `kept` (base index → head index), `removed`, or `added`.
- Animation: removed lines fold away (height and opacity to 0), added lines slide in, kept tokens travel from their base box to their head box (both layouts measured in the runtime after fonts load; positions interpolated with an ease). Changed tokens tint with the brand's add/del colors and settle.
- Camera `follow` frames the changed lines.
- Elision: show at most 14 lines (landscape) / 18 (vertical): all changed lines first, then context nearest them; elided runs collapse into one `⋯ N lines` marker (N computed by Covi). Choice deterministic.
- Code at ≥ 24 px at 1080p; the card sizes to its content (§8).

## 7. Numbers — PR B4

### 7.1 Metric evidence (additive; `evidence.json` stays `schemaVersion: 1`, R-010)

- `EVIDENCE_KINDS` gains `metric`. `EvidenceItemSchema` gains optional `metric: { name, unit?, base?, head? }` (strict; finite numbers, |v| < 1e15, ≤ 6 decimals; at least one side).
- Ids: `metric:<source>:<name>`: source `terminal-<n>` (demo command n), `http-<n>` (numeric JSON fields of a response body), `test-run`, `diff` (files, additions, deletions), `pixel-<scenario>-<step>` (changed-pixel share of a behavior-diff step). `name` is a slug `[a-z0-9-]{1,40}`; duplicates get `-2`, `-3`.
- Extraction (`packages/core/src/evidence/metrics.ts`, pure): per line `label: number [unit]` / `label = number [unit]`, inline `key=value` pairs, and numeric leaves of JSON output (depth ≤ 4). Thousands separators accepted. Units: up to 8 letters or `%`. Base and head pair by source and name. ≤ 50 metrics per source, ≤ 500 per run. Redaction runs before extraction, so a redacted number never becomes a metric.
- `covi evidence` lists metrics with their values.

### 7.2 Visuals

- `counter`: the value large (the largest text on screen, ≥ 120 px at 1080p), unit beside it, and Covi's computed delta (`−85%`) under it; `count` ticks base → head with an ease-out; digits use tabular figures; formatting is Covi's own deterministic grouping (no `Intl`).
- `bars`: base and head bars on one scale; the head bar grows or shrinks during `count`.
- `compare`: base and head values side by side with an arrow; head lands last.
- Derived numbers (deltas, ratios) are computed by Covi from evidence values, never written by the agent.

## 8. Density and monotony — PR B1

- Cards size their type to content: code and terminal text from 24 px up to 44 px (landscape) / 48 px (vertical) at 1080p; a short block renders large; the card grows to use the media region (centered, ≥ 60% of its area when content allows).
- `LayoutItem` gains `font?: number` (px as drawn, including the camera's scale) and `text?: 'code' | 'body' | 'meta'` (meta = chips, file paths, small labels; exempt).
- QC (all `warn`, R-007): `text-size` (code < 24 or body < 28 px at 1080p, measured relative to the frame's short side), `empty-frame` (settled content bounding box < 40% of the media region), `monotony` (> 2 consecutive story scenes of the same lead kind; with direction, a shot's lead kind is its first element's, `visual` resolved to the storyboard kind, flow-verb shots count as `flow`), `transition-variety` (one kind > 60% of story transitions, when there are ≥ 4).
- Benchmark example `examples/backend-slim-request/` (R-005): a small Node service whose `buildReviewRequest` embeds full documents in a request to a reader worker, chunked at a size limit (base), and after the change sends a list of document ids and titles while the reader fetches each document itself (head). A demo command (`node scripts/measure.js`) prints measured lines (`request bytes`, `chunks`, `reader steps`, `timeouts`) computed by the example's own code from bundled fixture documents written for Covi. Base tree, head overlay, `change.yml` with honest expectations.

## 9. Flow verbs — PR B5

Elements `node`, `packet`, `pile`; verbs `flow`, `split`, `merge`, `stack`, `count-up` (§4.2–4.3). Edges are drawn between node rects (straight or one elbow), packets travel along the edge path with an ease, splits fan pieces out from the source's box, merges pull them back, piles stack items in a grid of up to 12, then the counter shows the real number. A `label` with `tone: warning` stages "timed out"-type moments. This is the vocabulary for backend changes: request → chunks (split), reads pile up (stack, count-up), a timeout (warning label), after the change one list (merge).

## 10. Draft and critique loop — PR B6

- `covi render --run <id> --draft` (R-006): renders at half size and 15 fps into `video/draft/` (`preview.mp4`, `contact-sheet.jpg`, `qc.json`, `timeline.json`), reusing cached narration; it never touches the final render's files or `frames.json`.
- Motion QC (in both draft and final `qc.json`):
  - `motion-gap` (warn): longest stretch of narration with nothing moving > 1.5 s (motion intervals computed from the timeline: transitions, camera moves, beats, component choreography via `settledAt`, stop camera push).
  - `motion-busy` (warn): more than 3 beats starting within any 1 s, or more than 2 camera moves within 2 s.
  - `reading-time` (warn): text elements visible less than `0.4 s + characters / 15 s` (CJK: `/ 8`).
  - `overlap` (warn): direction element rects overlapping by > 4% of the smaller at settled frames (containment by design excluded).
  - `out-of-frame` (fail): an element rect outside the viewport clip at a settled frame.
- The `covi-video` skill: after drafting, render `--draft`, open `video/draft/contact-sheet.jpg`, read `video/draft/qc.json`, revise `direction.json`; at most 3 rounds, then a final render.

## 12. Broadcast mix — PR A1

### 12.1 Signal chain

```
music (rendered) → normalize −16 LUFS → glue compressor → re-normalize −16 LUFS
  → voice-band carve (dynamic EQ, during speech) → placement gain (smoothed) → music bus
voice (−16 LUFS) ─────────────────────────────────────────────────────────────► master
effects (gain relative to the bed, capped at voice peak − 8 dB) ─────────────► master → linear gain + limiter
```

- **Glue compressor** (`dsp/fx.ts`): stereo-linked RMS detector (≈ 50 ms), ratio 2:1, soft knee 6 dB, threshold −24 dBFS RMS (the stem sits at −16 LUFS, so peaks and dense passages are compressed by 1–3 dB and quiet passages not at all; a unit test pins the theme's typical reduction to 0.5–4 dB); attack 30 ms, release 400 ms; makeup by re-normalization. Deterministic, sample-accurate.
- **Voice-band carve**: `music − k(t)·BP(music)` with an RBJ constant-0-dB-peak band-pass at 2 kHz, Q 0.7 (covers ~1–4 kHz); `k` 0 in gaps, 0.5 (−6 dB at center) while someone speaks, following the same smoothed envelope as the duck.
- **Placement** (`placement.ts`): `continuous` is the default for every kind of video (R-004: `auto` resolves to `continuous`). Levels relative to the −16 LUFS stem: bed under speech −15 dB, gaps −8 dB (a 7 dB duck, bounded 6–10), intro and outro −6 dB. Duck starts ahead of speech so it is down when the line starts (pre-roll 1.2 s), recovers over 1.5 s after it, ramps are raised-cosine in dB, and gaps too short to reach the gap level and hold it ≥ 0.5 s stay ducked. Max slope keeps any 1 s change ≤ 6 dB by construction. `bookends` stays an option with slope-limited ramps (≤ 5 dB/s), so in short breaths it swells only partway.
- **Effects**: `sound-effects.yml` `gainDb` becomes relative to the bed's level under speech (R-011); after placement the mix lowers all effects together if their peak is within 8 dB of the voice's peak. `effectsBelowVoiceDb ≥ 8` always.
- `AUDIO_ENGINE_VERSION = 'covi-audio-4'`. Master −16 LUFS ± 0.5, true peak ≤ −1 dBTP (unchanged loop).
- Only the seeded PRNG; no clocks.

### 12.2 Measurement and QC

- `packages/audio/src/loudness.ts` gains `momentaryLoudness` (400 ms windows, 100 ms hop) and `loudnessRange` (EBU Tech 3342: 3 s short-term windows, absolute gate −70 LUFS, relative gate −20 LU, 95th − 10th percentile).
- `video/audio.json` `levels` gains `musicRangeLu` (narrated span: first line start → last line end) and `musicJumps` (largest momentary change within 1 s outside exempt windows, with its time).
- Exempt windows (documented in the skill and `docs/video.md`): intro `[0, firstLine + 1 s]`, hero `[downbeat − 1.5 s, downbeat + 1.5 s]`, outro `[lastLine − 0.5 s, end]`.
- QC: `music-jump` **fail** if > 6 dB within 1 s outside exempt windows; `music-range` **warn** if LRA > 8 LU; `music-under-speech` passes at 12–20 dB for `continuous` (warn outside, fail < 9).

## 13. Sound from motion — PR A2

- Timeline cues gain direction events (cues exist whatever the sound settings, so frames never depend on sound): `camera` (stop-to-stop `pan`/`zoom` and in-stop camera beats) → whoosh; `count`/`count-up` → `tick` (one cue carrying its duration, rendered as a tick train following the counter's ease); `merge` → `thump`; `reveal` → soft `accent`.
- New recipes in `templates/music/sfx/` pitched in C (note names; they follow the key via `effectTranspose`); cue map entries in `sound-effects.yml`.
- Mixed under A1 rules (relative to the bed, ≥ 8 dB under the voice peak, density limits; ticks count as one effect).
- Nothing in `timeline.json` depends on the sound choice.

## 14. Security (applies to every PR)

- Direction and storyboard are untrusted agent input; repository content reaches the agent.
- Strict schemas, bounds, label allowlist, evidence-only content, redaction of everything resolved, `textContent` only in the runtime. No field accepts CSS, HTML, URLs, selectors, or code.
- PR B2 adds `tests/direction-security.test.ts`: oversized lists, script-like strings (`<script>`, `javascript:`, `onerror=`), URLs, unknown evidence ids, made-up numbers (digits in labels, a `value` key on a metric) are rejected; a crafted label that passes validation renders as literal text (render test asserts no element was created from it and `textContent` equals the label).
- `docs/security.md` gains the direction file.

## 15. Testing strategy

- Unit tests per module (schema accepts/rejects, resolver, director determinism, tokenizer/alignment, metric extraction, DSP blocks, placement slopes, loudness range against known signals).
- Render tests (`npm run test:render`) per runtime feature: deterministic bytes for the same timeline, canvas stops, morph, metric, flow; QC checks over rendered layouts.
- Example tests: the benchmark's expectations; its default direction uses morph + metric + flow and passes non-render QC.
- Acceptance (§ prompt): ko and en renders of the benchmark, contact sheet + poster judged, ffmpeg ebur128 measurements, twice-rendered determinism.

## 17. Acceptance (verified before the program is called done)

1. Render the benchmark example in Korean and in English, standard 16:9, with theme music.
2. Open `video/contact-sheet.jpg` and `video/poster.png` and judge as a viewer: not slides; the key number change is the largest thing on screen when it lands; code visibly morphs; the problem is shown, not told.
3. `ffmpeg -v verbose -af ebur128` on each render's stems: music LRA over the narrated span ≤ 8 LU; no music jump > 6 dB within 1 s outside the documented moments; music 12–20 dB below the voice during speech; master −16 ± 1 LUFS, true peak ≤ −1 dBTP.
4. Same input rendered twice → identical `frames.json` sha256 and identical `music.wav` bytes.
5. `npm run check` (and `npm run test:render` locally) pass on every PR.
6. `tests/direction-security.test.ts` (§14).
